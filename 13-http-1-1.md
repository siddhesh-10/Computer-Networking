# Networking — Phase 13: HTTP/1.1

> **Goal:** Understand how HTTP/1.1 clients and servers exchange web requests and responses.

## 1. HTTP Request

```text
Request line
Headers
Blank line
Optional body
```

Example:

```http
GET /index.html HTTP/1.1
Host: example.com
Accept: text/html
```

---

## 2. HTTP Response

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1256
```

Then the response body follows.

---

## 3. Methods

| Method | Purpose |
|---|---|
| `GET` | Retrieve resource |
| `POST` | Submit/create data |
| `PUT` | Replace resource |
| `PATCH` | Partially update resource |
| `DELETE` | Delete resource |
| `HEAD` | Headers without body |
| `OPTIONS` | Ask about supported operations |

---

## 4. Status Codes

```text
1xx → Informational
2xx → Success
3xx → Redirection
4xx → Client error
5xx → Server error
```

Common examples:

```text
200 OK
201 Created
204 No Content

301 / 308 Redirect
304 Not Modified

400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
429 Too Many Requests

500 Internal Server Error
502 Bad Gateway
503 Service Unavailable
504 Gateway Timeout
```

---

## 5. Headers

Headers carry metadata.

Request:

```http
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
Cookie: session=abc
```

Response:

```http
Content-Type: text/html
Content-Length: 1256
Cache-Control: max-age=300
Set-Cookie: session=abc
```

Headers can control caching, authentication, content type, cookies, compression, and connection behavior.

---

## 6. Cookies

Server:

```http
Set-Cookie: session=abc123
```

Browser later sends:

```http
Cookie: session=abc123
```

Cookies allow applications to maintain state across otherwise stateless HTTP requests.

---

## 7. Persistent Connections / Keep-Alive

HTTP/1.1 normally supports persistent TCP connections.

Without reuse:

```text
Request → TCP connection → Response → Close
```

With reuse:

```text
One TCP connection
 ├── Request 1 → Response 1
 ├── Request 2 → Response 2
 └── Request 3 → Response 3
```

This avoids repeated TCP handshakes.

---

## 8. Content-Length

```http
Content-Length: 1256
```

means:

```text
Response body = 1256 bytes
```

It helps the receiver determine where the body ends while the connection remains open.

---

## 9. Chunked Encoding

HTTP/1.1 can use:

```http
Transfer-Encoding: chunked
```

when the complete body length is not known in advance.

Conceptually:

```text
Chunk size
Chunk data
Chunk size
Chunk data
0
```

The `0` chunk marks the end.

---

## 10. HTTP Caching

Browsers and intermediaries can cache responses.

Common headers:

```text
Cache-Control
ETag
Last-Modified
Expires
```

Example:

```http
Cache-Control: max-age=300
```

A fresh cached response can avoid another request to the origin.

---

## 11. Practical: Inspect HTTP Headers

Run:

```powershell
curl.exe -I https://example.com
```

Example:

```text
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1256
```

`-I` requests headers without downloading the normal response body.

---

## 12. Mental Model

```text
Browser
   ↓
HTTP request
   ↓
TCP connection
   ↓
Server
   ↓
HTTP response
   ↓
Browser
```

With persistence:

```text
One TCP connection
       ↓
Request/response
       ↓
Request/response
       ↓
Request/response
```

> HTTP defines the application-level protocol; TCP provides the reliable byte stream underneath it.
