# Networking — Phase 13: HTTP/1.1

> **Goal:** Understand HTTP/1.1 as an application-layer protocol, how it communicates over TCP, and how clients and servers exchange web resources.

## 1. What Is HTTP?

**HTTP (Hypertext Transfer Protocol)** is an **application-layer protocol** used for communication between clients and servers.

Typical stack:

```text
Browser / Application
        ↓
       HTTP
        ↓
       TCP
        ↓
       IP
        ↓
Ethernet / Wi-Fi
```

For traditional HTTP/1.1:

```text
HTTP/1.1
    ↓
TCP
    ↓
IP
```

HTTP defines:

```text
Request / response model
Methods
Status codes
Headers
Cookies
Caching
Message format
```

TCP provides:

```text
Reliable delivery
Ordered byte stream
Retransmission
Flow control
Congestion control
```

> HTTP defines **what the application communicates**; TCP provides the reliable transport underneath it.

---

## 2. Where HTTP Fits

| Layer | Protocol | Responsibility |
|---|---|---|
| Application | HTTP/1.1 | Web communication |
| Transport | TCP | Reliable byte stream |
| Network | IP | Host-to-host delivery |
| Link | Ethernet / Wi-Fi | Local network delivery |

```text
HTTP
 ↓
Application protocol

TCP
 ↓
Transport protocol

IP
 ↓
Network protocol

Ethernet / Wi-Fi
 ↓
Link layer
```

---

## 3. Client and Server

HTTP normally follows a **client-server model**.

```text
Client                         Server

Browser
   |
   | HTTP Request
   |-------------------------->
   |
   | HTTP Response
   |<--------------------------
   |
```

Example:

```text
Browser
   ↓
GET /index.html
   ↓
Web server
   ↓
HTML response
   ↓
Browser
```

The client initiates the request and the server sends a response.

---

## 4. HTTP Is Stateless

HTTP is generally **stateless**.

```text
Request 1:
GET /profile

Request 2:
GET /orders
```

HTTP does not inherently require the server to remember that both requests belong to the same user.

Applications add state using:

```text
Cookies
Sessions
Authorization tokens
Server-side storage
```

Example:

```text
Login
  ↓
Server creates session
  ↓
Set-Cookie
  ↓
Browser stores cookie
  ↓
Future requests include Cookie
```

---

## 5. HTTP Request

An HTTP/1.1 request contains:

```text
Request line
Headers
Blank line
Optional body
```

Example:

```http
GET /index.html HTTP/1.1
Host: example.com
Accept: text/html
```

The request line contains:

```text
Method   Path          Version
  ↓       ↓              ↓
 GET   /index.html   HTTP/1.1
```

---

## 6. HTTP Response

A response contains:

```text
Status line
Headers
Blank line
Optional body
```

Example:

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1256
```

Then the response body follows.

---

## 7. HTTP Methods

| Method | Purpose |
|---|---|
| `GET` | Retrieve a resource |
| `POST` | Submit data / create a resource |
| `PUT` | Replace a resource |
| `PATCH` | Partially update a resource |
| `DELETE` | Delete a resource |
| `HEAD` | Get headers without a response body |
| `OPTIONS` | Ask about supported operations |

Example:

```http
GET /users/123 HTTP/1.1
Host: example.com
```

## 8. HTTP Status Codes

```text
1xx → Informational
2xx → Success
3xx → Redirection
4xx → Client error
5xx → Server error
```

Common examples:

```text
200 OK
201 Created
204 No Content

301 Moved Permanently
302 Found
304 Not Modified
307 Temporary Redirect
308 Permanent Redirect

400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
429 Too Many Requests

500 Internal Server Error
502 Bad Gateway
503 Service Unavailable
504 Gateway Timeout
```

Useful first distinction:

```text
4xx
 ↓
Request/client-side problem

5xx
 ↓
Server/service-side problem
```

## 9. HTTP Headers

Headers carry metadata.

Request:

```http
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
Cookie: session=abc
```

Response:

```http
Content-Type: text/html
Content-Length: 1256
Cache-Control: max-age=300
Set-Cookie: session=abc
```

Headers can describe or control:

```text
Content
Caching
Authentication
Cookies
Compression
Connection behavior
```

---

## 10. Host Header

HTTP/1.1 requires the `Host` header for normal requests.

Example:

```http
GET /index.html HTTP/1.1
Host: www.example.com
```

Multiple websites can share one IP:

```text
93.184.216.34
       |
       +── www.example.com
       +── api.example.com
       +── shop.example.com
```

The hostname tells the server which virtual host the request targets.

---

## 11. Cookies

The server can send:

```http
Set-Cookie: session=abc123
```

The browser can later send:

```http
Cookie: session=abc123
```

Flow:

```text
Server
  ↓
Set-Cookie
  ↓
Browser stores cookie
  ↓
Future request
  ↓
Cookie header
```

Cookies are commonly used for:

```text
Sessions
Authentication state
Preferences
Tracking
```

---

## 12. Persistent Connections / Keep-Alive

HTTP/1.1 normally supports persistent TCP connections.

Without reuse:

```text
Request
  ↓
TCP connection
  ↓
Response
  ↓
Close
```

With persistence:

```text
One TCP connection
 ├── Request 1 → Response 1
 ├── Request 2 → Response 2
 └── Request 3 → Response 3
```

Benefits:

```text
Fewer TCP handshakes
Lower latency
Less connection churn
Less resource overhead
```

This connects directly to TCP connection pooling and lifecycle concepts from earlier phases.

---

## 13. Content-Length

Example:

```http
Content-Length: 1256
```

Meaning:

```text
Message body = 1256 bytes
```

It helps the receiver determine where the body ends while the TCP connection remains open.

---

## 14. Chunked Transfer Encoding

HTTP/1.1 can use:

```http
Transfer-Encoding: chunked
```

when the complete response length is not known before transmission.

Conceptually:

```text
Chunk size
Chunk data

Chunk size
Chunk data

0
```

Example:

```text
5
Hello
6
 World
0
```

The final `0` marks the end of the chunked body.

This allows a server to start sending data before it knows the final body size.

---

## 15. Content-Length vs Chunked Encoding

### Content-Length

```text
Content-Length: 1000
        ↓
Read 1000 bytes
```

### Chunked

```text
Transfer-Encoding: chunked
        ↓
Read chunks
        ↓
0-size chunk
        ↓
Body finished
```

They are alternative ways to determine the message-body boundary for a response.

---

## 16. HTTP Caching

Browsers, proxies, and other intermediaries can cache HTTP responses.

Common headers:

```text
Cache-Control
ETag
Last-Modified
Expires
```

Example:

```http
Cache-Control: max-age=300
```

Conceptually:

```text
Browser
   ↓
Request resource
   ↓
Cache
   ↓
Fresh?
 /   Yes   No
 ↓     ↓
Use   Request server
cache
```

Caching can reduce:

```text
Latency
Bandwidth usage
Server load
```

---

## 17. Conditional Requests

HTTP caching can use validators such as:

```text
ETag
Last-Modified
```

Example:

```http
ETag: "abc123"
```

Later:

```http
If-None-Match: "abc123"
```

If the resource has not changed:

```text
HTTP/1.1 304 Not Modified
```

The browser can reuse its cached copy.

## 19. HTTP/1.1 Limitations

HTTP/1.1 uses a byte stream over TCP.

When many resources are needed, clients historically opened multiple TCP connections:

```text
Connection 1 → Resource A
Connection 2 → Resource B
Connection 3 → Resource C
```

This increases:

```text
TCP handshake overhead
Connection count
Resource usage
```

HTTP/2 later introduced:

```text
Binary framing
Streams
Multiplexing
```

HTTP/3 later moved HTTP transport to:

```text
QUIC
 ↓
UDP
```

These are covered in Phase 14.

## 20. Practical: Inspect HTTP Headers

Run:

```powershell
curl.exe -I https://example.com
```

Example:

```text
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1256
Cache-Control: max-age=300
```

Meaning:

```text
200
 ↓
Request succeeded

Content-Type
 ↓
Response contains HTML

Content-Length
 ↓
Body size is 1256 bytes

Cache-Control
 ↓
Caching instructions
```

`-I` requests headers without downloading the normal response body.

---

## 21. Practical: Send a GET Request

Run:

```powershell
curl.exe https://example.com
```

Possible output:

```text
<!doctype html>
<html>
...
</html>
```

Meaning:

```text
curl
 ↓
HTTP GET
 ↓
Server
 ↓
HTTP response body
```

The exact HTML depends on the server.

---

## 22. Practical: Headers + Body

Run:

```powershell
curl.exe -i https://example.com
```

Possible output:

```text
HTTP/1.1 200 OK
Content-Type: text/html

<!doctype html>
<html>
...
```

Difference:

```text
-I
 ↓
Headers only

-i
 ↓
Headers + response body
```
